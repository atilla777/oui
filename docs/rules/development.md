# Разработка и MIS

## Существующий проект

- Основной код — Odin: выборочные пакеты `kit/`, примеры `consumer/`, проверки
  `tests/`. Python/Bash в `scripts/` — инструменты сопровождения, не runtime kit.
  Проверенная native-среда и версии описаны в [quickstart](../quickstart.md)
  и [resources](../resources.md); зависимости не устанавливаются и не обновляются
  автоматически ради задачи.
- Сохраняй существующие owners и направления зависимостей. UI-алгоритмы живут
  в kit/consumer, а не во второй реализации внутри tooling.
- Соблюдай явное владение, fallible prepare до commit, неавторитетность старых
  readers, явное восстановление без replay по [lifecycle](../lifecycle.md).
- Не меняй API/продуктовые границы ради зелёных тестов. Новые существенные
  требования и изменения гарантий согласуй с владельцем; не вводи обязательный
  TDD, новый стек или универсальный framework без решения проекта.

## Процесс

- `/mis-plan <цель>` планирует; `/mis-run <ID>` выполняет одну native Task/Bug;
  `/mis-status [ID]` только показывает состояние. Планирование не разрешает
  реализацию и не запускает следующую задачу.
- Достаточный контракт работы — цель, границы и проверяемые критерии в Beads
  со ссылками на относящиеся документы. Не нужен отдельный обязательный дизайн
  или реестр задач в Markdown.
- Изменения задач выполняются в отдельной ветке и linked worktree, созданной
  нативными средствами OpenCode, с переходом `session_move` и проверкой реальных
  путей. Сохраняй чужие изменения. Текущая подготовка MIS — локальная setup-операция;
  она не создаёт разрешения редактировать main для последующих Task.
- Beads — единственная canonical embedded БД в корне oui, prefix `oui`.
  Linked worktree должен использовать её же; не создавай вторую БД или соседний
  tracker. GitHub issue number не является Beads ID. Существующие Issues,
  зависимости и документы отдельной документационной ветки/PR сохраняются.
- После реализации синхронизируй [spec](../spec/index.md) и относящиеся контракты
  либо обоснуй no-op. Не выдавай старую квалификацию за проверку нового снимка.
- Перед публикацией обязательно независимое read-only ревью полного
  публикуемого снимка отдельным контекстом `advanced` через
  `mis-port-op-review-change`. Автор или исправитель не заменяет reviewer;
  после исправлений нужны затронутые перепроверки и re-review.
- Проверки и определение готовности — в [checks](checks.md). В результате
  указывай точную проверку/демонстрацию, ожидаемый эффект и ограничения.
- Git destination — `origin/main` репозитория `https://github.com/atilla777/oui.git`.
  Dolt remote — тот же репозиторий, история в `refs/dolt/data`. Это разные
  публикации с отдельным подтверждением. Указание destination **не разрешает push**:
  для Git и общей истории Dolt нужна явная власть на публикацию. Нет постоянного
  разрешения из факта установки MIS. Обычные локальные commits текущей установки
  разрешены; чужие изменения в них не включаются.
- Живую БД, locks, caches, credentials и артефакты запусков не коммить. MIS остаётся
  maintainer-only пакетом; его ревизия записана в `.opencode/mis-installation`.
