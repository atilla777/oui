# oui — назначение и границы

oui — экспериментальный набор выборочных Odin-пакетов для интерфейсов небольших
игр, а не игра, игровой движок или универсальный UI-фреймворк. Цель — позволить
разработчику взять нужную часть интерфейса без всего демонстрационного приложения
и без инструментов сопровождения этого репозитория.

## Основные принципы

- Headless layout, interaction/text, дополнительные семейства компонентов и
  SDL3 backend подключаются по необходимости. Потребитель явно выбирает пакеты,
  ресурсы и их зависимости по [рецептам](../recipes.md).
- Модель приложения и значимые значения принадлежат потребителю; библиотека
  предоставляет UI-механизмы с явным владением, временем жизни и обработкой ошибок.
- Примеры menu/showcase демонстрируют интеграцию, но не становятся обязательным
  каркасом игры. Обычная сборка/запуск не требует MIS, Beads, agent client,
  Python, генераторов, соседнего checkout или сети.
- API экспериментальный. Нет обещания совместимости со старым umbrella `ui`,
  произвольной композиции семейств или возможностей за пределами опубликованных
  [границ поддержки](../compatibility.md) и [карты scope](../scope.md).
- Лицензии и notices выбранных ресурсов сохраняются; собственная MIT-лицензия
  не перелицензирует сторонние шрифты, данные, codecs и инструменты.

Это краткое описание существующего назначения из [документации kit](../README.md),
не новый список функций, обещание стабильности или аттестация текущей сборки.
Подробные API-контракты остаются в существующих документах; результаты и пределы
проверок — в [qualification](../qualification.md).

Планы, задачи и статусы ведутся в Beads. Новые существенные продуктовые решения
согласуются с владельцем, а не выводятся автоматически из кода или плана MIS.
Правила сопровождения — в [rules](../rules/index.md), навигация по реализованному
поведению — в [spec](../spec/index.md).
