документы не перемещены и не объявлены результатами новых Beads-задач:

После MIS Task/Bug добавляй сюда или обновляй существующий документ по
функциональности: устойчивое реализованное и проверенное поведение, ограничения,
практическая проверка и настоящий Beads ID. Не дублируй API и не придумывай ID
для старой реализации. Чисто техническая задача может иметь обоснованный spec no-op.

Требования находятся в [product](../product/index.md), инженерные правила —
в [rules](../rules/index.md), очередь и статусы — только в Beads.
GitHub Issues и `docs/specs/1/` в отдельной документационной ветке/PR не
переносятся и не дублируются без явного решения о миграции.
